## 1 命令格式约定

| 项    | 规则                                            |
| ---- | --------------------------------------------- |
| 进命令态 | 静默 ≥1s → `+++` → 静默 ≥1s → `OK`（默认空密码自动解锁）     |
| 退命令态 | `ATO` → `OK`，退回数据模式并上锁                        |
| 写    | `AT+KEY=<值>` → `OK`；成功后落盘 `UserCfg @ 0x1D000` |
| 读    | `AT+KEY?` → `AT+KEY=<当前值>` + `OK`             |
| 执行   | `AT+XXX`（无参数），见 §2.4                          |
| 失败   | `ERROR`（未知 key、越界、未解锁、参数缺段）                   |
| 分隔   | 多段一律英文逗号 `,`（不用 `:`）                          |
| 通道   | 第 N 段 = 第 N 路 CH1..CHn；`0` = 关该路              |
| 短写   | 只写前 N 段 = 只改前 N 路，后面保持原值                      |
| 取值   | `?` 仅用于 `unit` `ran` 这类需要设备回显算出的值             |
| 串口   | LPUART0，115200 8N1，`\r\n` 或 `\n` 结尾           |

**生效时机** 各 key 不同，见「生效」列：`立即` / `下周期` / `重连` / `重启`。

**状态列**：**现行** = 已发布固件支持；**新增** = 统一 Key 新增，需固件补齐。

### 1.1 字段长度约定（全部字符串字段）

**唯一口径：按 UTF-8 字节计，不是字符数**。超长一律回 `ERROR` 且整条不写入，**不截断、不补零、不自动转码**；读回原样返回，远程 JSON 下发同字段同样整条丢弃。

| #  | 字段             | 出处                         | 上限                       | 说明                                    |
| -- | -------------- | -------------------------- | ------------------------ | ------------------------------------- |
| 1  | `model` 型号+固件  | `ver` 前两段 / 上报 `model`    | **20**                   | `WW75C,2.0.3`(12)；型号 ≤8 + `,` + 固件 ≤8 = 17 |
| 2  | `no` 设备编号      | 上报 `no` / `AT+INFO?`       | **16**                   | `WW75C`(5) + `24090007`(8) = 13，留 3 位 |
| 3  | `srv` 链路类型     | `server` 第 1 段（注册上报写在整串 `server` 内，**不**单独出 `srv`） | 5                        | 枚举 `TCP`/`MQTT`/`UDP`/`HTTP`，最长 5     |
| 4  | `host` 主机      | `server` 第 2 段（注册上报写在整串 `server` 内，**不**单独出 `host`） | 32                       | 域名或点分 IP；**不用 RFC 的 253**，设备侧按 64 收   |
| 5  | `port` 端口      | `server` 第 3 段（注册上报写在整串 `server` 内，**不**单独出 `port`） | **1~65535**              | 数值范围，非长度                              |
| 6  | `user` MQTT 账号 | `mqtt` 第 1 段               | 16                       |                                       |
| 7  | `pass` MQTT 密码 | `mqtt` 第 2 段               | 16                       | 允许任意可见 ASCII，含 `,` 需转义见 §1.2          |
| 8  | `cid` ClientID | `mqtt` 第 3 段               | 16                       | 常填 `no`（13 位）                         |
| 9  | `topic` 主题     | `mqtt` 第 4 段               | **48（发布、订阅各计）**          | 见 §5.6                                |
| 10 | `apn` 接入点      | `apn` 第 1 段                | 16                       | 运营商 APN 通常 ≤ 23                       |
| 11 | `apn` 账号       | `apn` 第 2 段                | 16                       |                                       |
| 12 | `apn` 密码       | `apn` 第 3 段                | 16                       |                                       |
| 13 | `iccid`        | 上报 / `AT+4G?`              | **20（固定 19~20）**         | 不足不补零，原样输出                            |
| 14 | `imei`         | 上报 / `AT+4G?`              | **15（固定）**               | 模组固定 15 位                             |
| 15 | `SER` 串口密码     | `AT+SER=`                  | **16**                   | 6 位数字为常用，留 16                         |
| 16 | `OTADATA` 分包   | `AT+OTADATA=`              | **512 字符/包**（= 256 B 固件） | 十六进制，偶数位                              |
| 17 | `ip` 本机地址      | `AT+INFO?` / `AT+4G?`      | **15**                   | IPv4 点分十进制；若上 IPv6 放宽到 **39**         |
| 18 | `mod` 模组型号     | `AT+INFO?`                 | **16**                   | 如 `EC800M`；超长截断为前 16                  |
| 19 | 上行数据包          | TCP/UDP/MQTT 上报            | **512 B**                | 设备 1 KB 缓冲的一半                         |
| 20 | 下行配置包          | 远程配置                       | **512 B**                | 与上行同口径                                |

**为什么卡这些数**：上表 1~16 项的取值受 Flash `UserCfg @ 0x1D000` 单条记录长度与 4G 模组 socket 缓冲限制，`host` 64 / `topic` 48 是可算出的上限，其余按现有最长的真实数据留 1~3 字节余量；19、20 两项是整包预算。数值类 key（`per` `var` `thre` `unit` `ran` `dly` `pls` `cfg_v` 等）的长度由取值范围定，见各 key 的「值」列，不在此表重复。

### 1.2 分隔符与转义

多段用 `,` 分隔，值里本身含 `,` 时（主要是 `pass`）按 `\,` 转义；含 `\` 写 `\\`。**不支持引号包裹**，也不做 URL 编码。远程 JSON 里的 `pass` 直接写原值，由 JSON 自身的 `"` 定界，不需要 `\,`。

# 第一部分 · 通用型

所有传感器都支持的 14 个 key，与型号无关，平台侧一张表单覆盖全系。

## 2.1 采集与判定（6 key + `AT+ZERO` 执行）

| key    | AT 指令      | 值               | 默认                 | 状态 | 生效  |
| ------ | ---------- | --------------- | ------------------ | -- | --- |
| `per`  | `AT+PER=`  | `检测秒,上报秒`       | `60,600`           | 现行 | 下周期 |
| `var`  | `AT+VAR=`  | 按通道，0.01        | 温度 `50` / 压力 `200` | 现行 | 下周期 |
| `cal`  | `AT+CAL=`  | **按类型分段**，见下表   | `0`                | 新增 | 立即  |
| `thre` | `AT+THRE=` | `上限,下限` 或 `OFF` | `8000,-2000`       | 现行 | 下周期 |
| `ack`  | `AT+ACK=`  | `0/1`           | `0`                | 新增 | 立即  |
| `cfg_v` | `AT+CFG_V=` | 整数 `1~255`（1 字节） | `1`            | 新增 | 立即  |

- `per=0,0` 关闭周期上报，仅保留按键 / 中断 / `AT+REPORT` 触发。
- `var` 段为 `0` = 关该路变化上报；`thre=OFF` = 关阈值判定。
- `cal` 是校准偏移，**同一个 key 在不同类型下段序不同**，见下方「cal 分段含义」，不要跨类型套用。
- `AT+ZERO`（执行，非 key）：以**当前采样值**为新零点，等价自动写入校准偏移使当前读数显示为 0；与 `AT+CAL` 手工写偏移互补。**只执行、不单独查询**；执行后可用 `AT+CAL?` 读回已写入的偏移。网关无采集，不支持本指令。
- `thre` 语义随类型变：温湿度/压力/气体 = 上下限；运动类 = 触发阈值；IO 类不适用（写 `OFF`）。
- `ack=1` 时每次配置落地后设备主动回一字符。**4G 链路不校验内容，收到任意字符即视为 OK**（惯例回 `A`）；`AT+ACK` 不带参数 = 立即回 `A` 一次。
- `cfg_v` 是**配置版本号**，整数、占 **1 字节**（`1~255`，`0` 保留表示「未配置」）。每次配置成功写入（AT 或远程）设备**自动 +1**，`255` 回绕到 `1`；上报报文携带当前值，平台比对「下发前」与「下一包」是否 +1，即可确认配置已落地。**写 `cfg_v` 本身是设置基线，不再自增**（否则会出现自己 +1 自己的循环）。

### cal 分段含义（按类型区分）

| 类型    | 段序                                     | 单位                                    | 示例               |
| ----- | -------------------------------------- | ------------------------------------- | ---------------- |
| 温湿度类  | `温度,湿度`（多路按「路」展开：CH1 温, CH1 湿, CH2 温…） | 0.01 ℃ / 0.01 %RH                     | `AT+CAL=-30,150` |
| IO 类  | 不适用（数字量无偏移）                            | —                                     | `AT+CAL=0`       |
| 气体类   | `浓度`                                   | ppm                                   | `AT+CAL=-50`     |
| 运动类   | `X,Y,Z`；振动为 `振幅`                       | 0.01 ° / mg                           | `AT+CAL=0,0,-20` |
| 压力类   | `单位,压力`                                | 第 1 段 0~5（同 `unit` 枚举）；第 2 段 0.01 kPa | `AT+CAL=1,-120`  |
| 计量计数类 | `电压,电流,功率`                             | 0.01 V / 0.01 A / 0.01 W              | `AT+CAL=0,20,0`  |
| 控制类   | 不适用                                    | —                                     | —                |
| 网关类   | 不适用                                    | —                                     | —                |

> 压力类的「单位, 压力」两段序是现行固件行为：第 1 段同时决定压力值的显示单位，第 2 段才是校准偏移。温湿度、气体、运动、计量四类的段序是本次统一约定，固件按型号对应的段数实现（见 §7 兼容表）；段数与类型不符时回 `ERROR`。

**逐 key 示例（每个 AT 一条，可直接粘贴）**

```
AT+PER=60,300        # 每 60 s 采一次，每 300 s 上报一次
AT+PER=0,0           # 关周期上报，只靠按键 / 中断 / AT+REPORT

AT+VAR=50,200        # CH1 变化 0.50 报，CH2 变化 2.00 报；后面的路保持不变
AT+VAR=0,0           # 两路都关变化上报，只按周期报

AT+CAL=-30,150       # 温湿度：温度 -0.30℃，湿度 +1.50 %RH
AT+CAL=1,-120        # 压力：单位 kPa，压力 -1.20 kPa
AT+CAL=-50           # 气体：浓度 -50 ppm
AT+CAL=0,0,-20       # 运动（倾角）：X/Y 不偏，Z 轴 -0.20°
AT+CAL=0,20,0        # 计量：电流 +0.20 A，电压与功率不偏

AT+ZERO              # 以当前采样为新零点（自动写偏移；再 AT+CAL? 可读回）

AT+THRE=8000,-2000   # 上限 80.00，下限 -20.00（0.01 为单位）
AT+THRE=OFF          # 关阈值判定（IO 类必须这么写）

AT+ACK=1             # 开应答：每次配置落地后回一个 A
AT+ACK               # 不带参数 = 立即回 A 一次（链路探测）

AT+CFG_V?            # 读配置版本，如回 AT+CFG_V=7
AT+CFG_V=1           # 手动把版本基线归 1（换平台、重建档时用；一般不用写）
```

**读回示例**

```
AT+PER?   → AT+PER=60,300 + OK
AT+VAR?   → AT+VAR=50,200 + OK
AT+CAL?   → AT+CAL=-30,150 + OK（温湿度）= 温度/湿度各一段
           AT+CAL=1,-120 + OK（压力）= 单位/压力各一段
AT+THRE?  → AT+THRE=8000,-2000 + OK
AT+ACK?   → AT+ACK=1 + OK
AT+CFG_V? → AT+CFG_V=7 + OK（当前配置已是第 7 版）
```

## 2.2 4G网络与监听

本分册只覆盖 **4G网络**（`server` / `mqtt` / `apn` / `AT+4G?`）与上报后监听窗口 `lis`。LoRa 射频参数见 LoRa 分册。

### 2.2.1 4G网络


| key      | AT 指令        | 值                                               | 默认    | 状态 | 生效 |
| -------- | ------------ | ----------------------------------------------- | ----- | -- | -- |
| `server` | `AT+SERVER=` | `类型(≤8),主机(≤64),端口(1~65535)`                    | 编译宏   | 现行 | 重连 |
| `mqtt`   | `AT+MQTT=`   | `用户(≤32),密码(≤32),ClientID(≤32),发布主题/订阅主题(各≤48)` | 编译宏   | 现行 | 重连 |
| `apn`    | `AT+APN=`    | `apn(≤32),用户(≤32),密码(≤32)`                      | 空（自动） | 新增 | 重连 |
| —        | `AT+4G?`     | 查询信号与卡信息（非 key）                                 | —     | 现行 | 即时 |

- `server` 类型：`TCP` / `MQTT` / `UDP` / `HTTP`，大小写不敏感；查询固定回 `AT+Server=`（历史大小写，回显保持原样）。
- `mqtt` 第 4 段含 `/` 时前为发布主题、后为订阅主题；单主题则收发同用。
- `mqtt` 的**每条主题（发布、订阅分别计）最长 48 字符**，按 UTF-8 字节计，`/` 与层级都算在内；超长整条 `AT+MQTT` 回 `ERROR` 且不写入，**不截断、不自动补全**。
- `apn` 空段 = 不改该项；三段全空 = 恢复自动取卡 APN。
- `AT+4G?`：读 `csq` / `iccid` / `imei` / `ip`，单项失败为 `-1` 或空串；属 **4G网络**，仅 C 后缀型号；细则与联调示例见 §2.4。

**逐 key 示例（每个 AT 一条，可直接粘贴）**

```
AT+SERVER=TCP,81.71.164.182,20004         # TCP 直连平台
AT+SERVER=MQTT,iot.wwiot.com,1883         # 改走 MQTT
AT+SERVER=HTTP,api.wwiot.com,80           # 改走 HTTP

AT+MQTT=wwiot,Pass@2026,WW75C0007,up/data                    # 单主题：收发同用
AT+MQTT=wwiot,Pass@2026,WW75C0007,up/data/down/ctrl          # 前发布，后订阅

AT+APN=CMNET                             # 只改 APN，账号密码保持原值
AT+APN=CMNET,card,123456                 # 专用物联网卡三段全写
AT+APN=,,                                # 三段全空 = 恢复自动取卡 APN

AT+4G?                                   # → csq=23,iccid=8986...,imei=8612...,ip=10.64.3.7
```

**读回示例**

```
AT+SERVER?  → AT+Server=TCP,81.71.164.182,20004 + OK
AT+MQTT?    → AT+MQTT=wwiot,Pass@2026,WW75C0007,up/data + OK
AT+APN?     → AT+APN=CMNET,, + OK
```

> `server` / `mqtt` / `apn` 改完都是**重连生效**：写完不断链要等下一次重连，或执行 `AT+RST` 立即生效。  
> 主题长度超 48 字符的处理：`AT+MQTT` 回 `ERROR`，原有配置保持不变（不会写一半）；远程 JSON 下发 `mqtt` 同样整条丢弃，其余 key 正常写入。

### 2.2.2 监听窗口 `AT+LIS`

| key   | AT 指令     | 值                    | 默认 | 状态 | 生效 |
| ----- | --------- | -------------------- | -- | -- | -- |
| `lis` | `AT+LIS=` | 秒（`1~30`，`0` = 关闭） | `3` | 新增 | 立即 |

- **每次上报完成后监听配置下发的时间窗**，默认 3 秒；`0` = 不留窗口，纯单向上报。取值 1~30，越界回 `ERROR`。
- 窗口行为与时序见 §5.2、§5.4。LoRa 侧同名指令见 LoRa 分册。

```
AT+LIS=3                                 # 上报后监听 3 s 收配置（默认）
AT+LIS=10                                # 现场网络差、平台响应慢，放宽到 10 s
AT+LIS=0                                 # 不留窗口，只上报不收（省电）
AT+LIS?  → AT+LIS=3 + OK
```

> `lis` 是**立即生效**，下个上报周期就按新窗口走，不用重启。

## 2.3 系统（4）

| key   | AT 指令      | 值                          | 默认         | 状态 | 生效 |
| ----- | ---------- | -------------------------- | ---------- | -- | -- |
| `ver` | `AT+VER=`  | `型号(≤8),固件版本(≤8)` | 编译宏        | 现行 | 重启 |
| `log` | `AT+LOG=`  | `0/1`                      | `0`        | 现行 | 立即 |
| `rst` | `AT+RST=`  | `小时,网络失败次,传感器失败次`          | `24,10,10` | 现行 | 立即 |
| `tt`  | —（JSON 专用） | Unix 秒                     | `0`        | 现行 | 立即 |

- `ver`：两段 `AT+VER=WW75C,2.0.3`（型号,固件版本），与上报 `model` 字段同源。**硬件版本已取消**，不再上送；旧固件若回三段（多一个硬件版本），平台只取前两段、第三段忽略。`AT+OTA=1` 回的 `AT+FW=203` 才是编译固件号。
- `log` 只关串口调试输出，`OK/ERROR` 与 JSON 应答不受影响。
- `rst` 任一条件命中即软重启。
- `tt` 只能由服务器下发 JSON 携带，无 AT 写入形式；设备侧 `AT+INFO?` 可查当前时间。

**逐 key 示例（每个 AT 一条，可直接粘贴）**

```
AT+VER=WW75C,2.0.3             # 型号 WW75C，固件 2.0.3
AT+VER=WW73C,2.1.0             # 换型号必须与实物一致，注册包同源

AT+LOG=1                       # 开串口调试日志（不影响 OK/ERROR 与 JSON）
AT+LOG=0                       # 关日志，量产默认

AT+RST=24,10,10                # 满 24 h 重启；网络连败 10 次重启；传感器连败 10 次重启
AT+RST=0,10,10                 # 不按时间重启，只保留失败计数重启

{"cfg_v":1,"tt":1793970000}      # tt 无 AT 形式，走远程 JSON 校时
AT+INFO?                       # 校时后看 ts 是否已更新
```

**读回示例**

```
AT+VER?   → AT+VER=WW75C,2.0.3 + OK（旧固件可能多一段硬件版本）
AT+LOG?   → AT+LOG=1 + OK
AT+RST?   → AT+RST=24,10,10 + OK
```

> `ver` 是**只读项**，写入仅用于产线烧录后校准；现场改型号串会导致平台建档错乱，不要动。  
> `tt` 对时结果用 `AT+INFO?` 看，里面 `ts` 就是设备当前时间。

## 2.4 控制与查询类指令（非 key）

| 指令             | 形态 | 示例                       | 说明 / 应答                                                           |
| -------------- | -- | ------------------------ | ----------------------------------------------------------------- |
| `+++`          | 执行 | `+++`                    | 进命令态，前后各静默 ≥1 s → `OK`                                            |
| `ATO`          | 执行 | `ATO`                    | 回数据模式并上锁 → `OK`                                                   |
| `ATH`          | 查询 | `ATH`                    | **列出本机支持的全部 AT 指令**，一行一条、以 `OK` 结束；平台据此判断该型号支持哪些项 |
| `ATR` / `AT+R` | 执行 | `ATR`                    | 软重启 → `OK` 后复位                                                    |
| `AT`           | 执行 | `AT`                     | 连通性测试 → `OK`                                                      |
| `AT+SER=`      | 写  | `AT+SER=123456`          | 解锁 / 改密 / 置空（`AT+SER=`），密码 ≤16；`AT+SER?` 回 `ERROR`                |
| `AT+DATA?`     | 查询 | `AT+DATA?`               | 立即采样，回数据包 JSON（`evt=0`，`seq` 不递增）                                 |
| `AT+INFO?`     | 查询 | `AT+INFO?`               | 设备状态：`no/model/fw/mod/bat/csq/ip/log/imei/iccid`（`bat`=`电量%,毫伏`）           |
| `AT+4G?`       | 查询 | `AT+4G?`                 | **属 4G网络**（§2.2.1）：→ `csq=23,iccid=8986...,imei=8612...,ip=10.64.3.7`，单项失败为 `-1` 或空串 |
| `AT+ZERO`      | 执行 | `AT+ZERO`                | 以当前采样为新零点（写入偏移使当前读数=0）→ `OK`；只执行、不单独查询；网关不支持 |
| `AT+REPORT`    | 执行 | `AT+REPORT`              | 立即上报一次（`evt=2`），不改 Flash → `OK`                                   |
| `AT+OTA=1`     | 执行 | `AT+OTA=1`               | 武装 OTA → `AT+FW=203`                                              |
| `AT+OTADATA=`  | 执行 | `AT+OTADATA=0000A1B2...` | 十六进制分包升级，每包 ≤512 字符（256 B），需 commit 后生效                           |
| `WW-M1 二进制帧`   | 执行 | —                        | 数据模式下即可用的串口 OTA，非文本命令                                             |

**逐条示例（按顺序执行一遍即为完整联调流程）**

```
+++                        → OK            进命令态
AT                         → OK            链路通
AT+SER=123456              → OK            解锁（空密码设备可跳过）
AT+VER?                    → AT+VER=WW75C,2.0.3
AT+INFO?                   → no=WW75C24090007,model=WW75C,fw=2.0.3,...
AT+4G?                     → csq=23,iccid=89860012345678901234,imei=861234567890123,ip=10.64.3.7
AT+DATA?                   → {"no":"WW75C24090007","evt":0,"ok":1,"t":2350,...}
AT+REPORT                  → OK            随后发一包 evt=2
AT+OTA=1                   → AT+FW=203    武装升级（需要时才用）
AT+OTADATA=0000A1B2...     → OK            分包写入，最后 commit
ATH                        → 逐行列出全部指令 + OK    看这台机器到底支持哪些项
ATO                        → OK            回数据模式
ATR                        → OK            复位（配置已落盘，重启不丢）
```

命令态 60 秒无操作自动退出并上锁；未解锁时只有 `AT` `ATO` `ATH` `AT+SER=` 有效。

**`ATH` 输出格式**

一行一条，只给指令名，**不带 `=` 前缀参数、不带默认值**，按「通用型 → 类型 → 控制与查询」顺序排列，末尾 `OK` 收尾。不同型号行数不同（网关类没有 `AT+THRE=`，IO 类没有 `AT+UNIT=`）。

```
ATH
AT+PER
AT+VAR
AT+CAL
AT+ZERO
AT+THRE
AT+ACK
AT+CFG_V
AT+SERVER
AT+MQTT
AT+APN
AT+LIS
AT+VER
AT+LOG
AT+RST
AT+UNIT
AT+RAN
AT+SER=
AT+INFO?
AT+DATA?
AT+4G?
AT+REPORT
AT+OTA=
AT+OTADATA=
OK
```

**怎么用 `ATH` 判断能力**

`ATH` 是唯一的能力查询入口，返回项分两类，用途完全不同：

| 返回项 | 类型 | 能不能当配置下发 |
|---|---|---|
| `AT+PER` `AT+THRE` `AT+UNIT` … | 可配置 key | 能，`AT+KEY=` / 远程 JSON 都行 |
| `AT+INFO?` `AT+DATA?` `AT+REPORT` `AT+OTA=` … | 执行 / 查询指令 | **不能**，只能下发执行，不带值 |

平台上位机对接：连上先跑一次 `ATH`，把返回的清单存成该机型的支持项；配置表单只渲染清单里出现的可配置 key，下发前也按这份清单校验，不在清单里的 key 直接拦掉，不下发。

**`ATH` / `ATO` / `ATR` 别再混**

| 指令 | 作用 | 动链路 | 复位 |
|---|---|---|---|
| `ATH` | 列出支持的指令（只读查询） | 否 | 否 |
| `ATO` | 回数据模式并上锁 | 否 | 否 |
| `ATR` | 软重启 | 是 | 是 |

`ATH` 是纯查询，**不落盘、不改配置、不断链路**。

## 3.1 温湿度类

**可用**：通用型全部 + `tun`

**成员（本分册）**：温湿度 `WW-10C`/`11C`/`12C`、测温杆 `WW-13C`、热电偶 `WW-15C-K`（LoRa 同族与 `WW-16L` 见 LoRa 分册；有线 RS 见 §3.0.5）

`var` `thre` 按通道展开，第 N 段 = CHN；温湿度款按「路」交替（CH1 温度, CH1 湿度…）。

```
AT+TUN=0
AT+CAL=-30,150                       # 温度 -0.30℃，湿度 +1.50 %RH
AT+VAR=50,100,0,0                    # CH1 变化 0.50℃，CH2 1.00℃，CH3/CH4 关
AT+THRE=8000,-2000,6000,0,OFF,OFF    # CH1/CH2 有阈值，CH3/CH4 关
```

- `cal` 段序 = `温度,湿度`；多路款按「路」展开：`CH1 温, CH1 湿, CH2 温, CH2 湿…`。
- 纯温度款（测温杆、热电偶、母线）只有温度一段：`AT+CAL=-30`。
- 单路温湿度只写两段：`AT+VAR=50,200`（温度 0.50℃，湿度 2.00%RH）。
- 湿度目前只参与 `var` 变化上报，`thre` 不判湿度。
- 热电偶额外上报冷端 `tc`，阈值仍走 `thre`。

## 3.2 IO 类

**可用**：通用型全部，**无专属 key**

**成员（本分册）**：水浸 `WW-20C`/`26C`、门磁 `WW-27C` / 双门磁 `WW-27C-D`、人体感应 `WW-21C`、**人体存在/跌倒多传感 `WW-25C`**、烟感 `WW-22C`、SOS `WW-28C`（LoRa / SL 系列见 LoRa 分册）

- `var` 的 0.01 数值无物理意义，语义为「状态变化即报」：写 `1` 触发上报，写 `0` 关该路。
- `thre` 不适用，**必须显式写 `AT+THRE=OFF`**，否则继承默认的 8000/-2000 会误判报警。
- `cal` 不适用：数字量没有偏移概念，写 `AT+CAL=0` 即可，勿写非 0 值。
- 主要靠 `per` 定心跳 + 中断定事件。

```
AT+THRE=OFF
AT+CAL=0
AT+VAR=1,1
AT+PER=60,3600
```

### 3.2.1 人体存在 / 跌倒多传感（WW-25C）

**型号串**：`WW25C`（`AT+VER=WW25C,200` 等）。传感器：SHT40 温湿度 · BH1750 光照 · P824M 红外 · LD6003C 跌倒雷达。

与纯 IO 的 `WW-21C`（仅 `pir`）不同，本款**同时**上报环境量与人体/跌倒状态，配置侧：

- `AT+PER=<检测秒>,<上报秒>`：检测采温湿/光照/PIR/雷达；上报周期到发心跳
- `AT+VAR=<ΔT>,<ΔRH>`：温湿相对上次成功上报基准的变化量（0.01 ℃ / 0.01 %RH）
- `AT+THRE=<hi>,<lo>`：**温度阈值**（0.01 ℃），可 `OFF`；**不要**像纯 IO 那样一律强制 `OFF`（除非现场不需要温限）
- 跌倒 / 驻留**上升沿**优先报 `evt=3`（告警），高于温湿变化 `evt=1`
- 4G 网络：`AT+SERVER` / `AT+MQTT` / `AT+APN` / `AT+4G?` 同其它 C 款
- 调试（可选）：`AT+I2C?`、`AT+RAD?`（产品手册）

上报本型 key 见 **§6.3.0 / §6.3.2**：`t` `rh` `lux` `pir` `pres` `fall` `stay` `mot` `mlvl`。


## 3.3 气体类

**可用**：通用型全部，**无专属 key**

**成员**：本分册暂无 4G 气体款；`WW-30L-CO2` / `WW-30L-O2` 见 LoRa 分册（能力集可参考本节 `cal`/`thre`/`var` 语义）

- `cal` 段序 = `浓度`，只有一段，单位 ppm，偏移量加在原始浓度上。
- `thre` 按浓度上下限判，`var` 按浓度变化量报。
- 部分型号带温湿度补偿，`t` `rh` 随气体值一起上报。

```
AT+CAL=-50         # 浓度 -50 ppm（现场比对偏高时用负值往下压）
AT+THRE=1000,400   # CO₂ 上限 1000 ppm，下限 400 ppm
AT+VAR=50          # 变化 50 ppm 上报
```

## 3.4 运动类（加速度、角度）

**可用**：通用型全部，**无专属 key**

**成员（本分册）**：倾角 `WW-50C`（含 `-P2`）；振动 `WW-51L` 见 LoRa 分册

- `thre` 语义变为**触发阈值**（不是上下限）：倾角按 0.01°，振动按 mg。
- `var` = 角度 / 加速度变化量。
- `cal` 段序：倾角 `X,Y,Z`（0.01°），振动只有振幅一段（mg）。
- 倾角走静态判定，振动走动态采样，两者阈值方向相反（倾角是「超过即报」，振动是「大于即报」）。

```
AT+THRE=300,0        # 倾角 3.00° 触发
AT+VAR=50            # 变化 0.50° 上报
AT+CAL=0,0,-20       # X/Y 不偏，Z 轴 -0.20°（安装面不平用这个压）

AT+THRE=200,0        # 振动 200 mg 触发
AT+VAR=50            # 振幅变化 50 mg 上报
AT+CAL=0             # 振动只有振幅一段
```

## 3.5 压力类

**可用**：通用型全部 + `unit` `ran`（温压一体另加 `tun`）；**无 `dly`**

**成员（本分册）**：压力 `WW-70C`、液位 `WW-73C`、拉力 `WW-78C`、温压一体 `WW-71C-P1`/`WW-75C`（`WW-72L`/`WW-74L` 等纯 LoRa 见 LoRa 分册）

```
AT+UNIT=1        # kPa
AT+RAN=0,2500    # 0~2500 kPa（即 0~2.5 MPa）
AT+CAL=1,-120    # 单位 kPa，压力 -1.20 kPa（两段：单位 + 偏移）
AT+ZERO          # 或以当前压力采样一键校零（再 AT+CAL? 看偏移）
AT+THRE=2500,0   # 上限 25.00 kPa，下限 0
```

- `cal` 段序是 **`单位,压力`**，和其他类型不一样：第 1 段填 `unit` 枚举（`0` Pa / `1` kPa / `2` MPa / `3` bar / `4` cm / `5` m），第 2 段才是校准偏移（0.01 kPa）。**不要把温湿度的「温度,湿度」写法套到这里**。
- `thre` **固定按 0.01 kPa 记**，与 `unit` 显示单位无关，换单位不改阈值。
- `ran` 改后下一次采样立即按新量程归一化，不改 `ran` 时芯体按出厂量程算。
- 压力类**没有 `dly`**：上电即采，不需要等待稳定；下发 `AT+DLY=` 回 `ERROR`（`dly` 只属于采集器，见 §3.6）。

**液位子型**（WW-73）

```
AT+UNIT=5        # m
AT+RAN=0,5       # 0~5 m
AT+CAL=5,-30     # 单位 m，压力偏移 -0.30 kPa（等效零点下移约 3 cm）
AT+THRE=450,50   # 上限 4.50 m，下限 0.50 m
```

液位 `cal` 的第 2 段同样按 **0.01 kPa** 记（与 `thre` 一致），不是按米，现场调零点时按 1 kPa ≈ 10.2 cm 水柱换算。

旧固件只发 `p` + `u=4/5`；新固件双发 `l`（0.001 m）。固件 `2.1.0` 起平台以 `l` 为准，`p` 仅做兼容（版本取上报 `model` 第 2 段）。

**温压一体子型**（WW-71C-P1 / 75C）

`thre` 取四段：`温度上限,温度下限,压力上限,压力下限`

```
AT+UNIT=1
AT+RAN=0,2500
AT+TUN=0
AT+CAL=1,-120,-30             # 单位 kPa、压力 -1.20 kPa、温度 -0.30℃（三段）
AT+THRE=8000,-2000,2500,0     # 温度 80/-20℃；压力 25.00/0 kPa
AT+VAR=50,200                 # 温度 0.50℃，压力 2.00 kPa
```

> 温压一体 `cal` 是 **`单位,压力,温度`** 三段：前两段与纯压力款完全一致，第三段才是温度偏移。四段式 `thre` 与三段式 `cal` 都是本次新增约定，旧固件只认两段，平台按固件版本（`model` 第 2 段）决定下发段数（见 §7）。

## 3.6 计量计数类

**可用**：通用型全部 + `pwr` `dly`（**仅采集器**；电力计量无专属 key）

**成员（本分册）**：电力计量 `WW-61C`、采集器 `WW-D1C`/`D2C`/`D3C`（`WW-60L` 与 L 族见 LoRa 分册）

```
AT+PWR=2,1       # 采集前供电 2s，采完保持 1s（采集器）
AT+DLY=3         # 上电等 3 s 再启动首轮采集（采集器）
AT+PER=30,300
AT+CAL=0,20,0    # 电压不偏，电流 +0.20 A，功率不偏（三段）
AT+VAR=100,50,50    # 电压 1V / 电流 0.5A / 功率 0.5W 变化即报
```

- `cal` 段序 = `电压,电流,功率`，单位依次 0.01 V / 0.01 A / 0.01 W。
- `pwr` 只对采集器（外接 RS485 / 4~20 mA）有效，控制外接传感器的供电时序。
- `dly` 也只对采集器有效：上电（或首次供电）到首次采样的等待秒数，给外接传感器留稳定时间。电力计量款下发 `dly` 回 `ERROR`。
- 电力计量无专属 key，`var` `thre` 按「电压, 电流, 功率」分段。
- 从站参数（波特率、地址、协议）走采集器专用配置串，不进本表。

## 3.7 控制类

**可用**：通用型全部 + `io` `omd` `pls`

**成员（本分册）**：`WW-C10C` ~ `WW-C17C`、`WW-C18C`（L 族见 LoRa 分册）

```
AT+OMD=2         # 脉冲模式
AT+PLS=500       # 脉宽 500 ms
AT+IO=1          # CH1 输出通（脉冲模式下触发一次）
```

- `omd` 输出模式：`0` 关 / `1` 常开 / `2` 脉冲 / `3` 跟随报警。
- `io` 按通道写，第 N 段 = CHN；`0` = 断。
- `cal` 不适用：控制类没有测量量，写 `AT+CAL=0` 或不下发。
- `omd=3` 跟随报警时 `io` 由判定逻辑接管，手动写 `AT+IO=` 会被下一次判定覆盖。

## 3.8 网关类

**可用**：通用型全部，**无专属 key**

**成员（本分册）**：`WW-G0-C`、`WW-G1` / `G1-610` / `G2` / `G3` / `G6-B`（`WW-M0-1302`、G0-RJ/RS 等 LoRa 侧见 LoRa 分册）

- 网关不采传感器，只转发，配置项就是网络 + 系统两部分，没有类别 key。
- `per` 在网关侧含义为「心跳秒, 状态上报秒」，`var` `thre` `cal` `AT+ZERO` 不适用（写了返回 `ERROR` 或无效）。
- 子设备台账、白名单、转发规则走网关专用配置接口，不在本手册范围。

```
AT+SERVER=TCP,81.71.164.182,20004
AT+PER=60,600
AT+LOG=0
```

# 第三部分 · 远程配置

AT 能配的 key，远程都能配；两边的 key 名、段序、取值完全同一套，平台不用维护第二份映射表。

本分册承载方式：**TCP / UDP / MQTT 发 JSON**（§5.3）。LoRa 下行（LoRaWAN 功能码 / 私有寄存器 / 编号+AT）见 **[LoRa 分册](./at-remote-config-lora.md)**。

## 5.1 一条链路收发

**设备用什么方式发数据，就用什么方式收配置**——不另开通道、不另配端口。

| 链路       | 上行（设备→平台）            | 下行（平台→设备，收配置）          | 配置方式                                                         |
| -------- | -------------------- | ---------------------- | ------------------------------------------------------------ |
| **TCP**  | 连 `host:port` 发 JSON | **同一条 TCP 连接**回一包 JSON | `AT+SERVER=TCP,host,port`                                    |
| **UDP**  | 发到 `host:port`       | 同 socket 同端口等回包        | `AT+SERVER=UDP,host,port`                                    |
| **MQTT** | 发布到第 4 段主题           | 订阅第 5 段主题              | `AT+SERVER=MQTT,host,port` + `AT+MQTT=user,pass,cid,pub/sub` |

- TCP / UDP 是**短连接 + 回包窗口**：设备上报完不立刻断开，留一个窗口等配置。
- MQTT 是**长连接订阅**：配置随时可下发，不受窗口限制，窗口只用来等发布回执。
- TCP / UDP / MQTT 三种链路的配置包格式完全相同（JSON），见 5.3。
- LoRa 空口不用 JSON，见 LoRa 分册。

## 5.2 监听窗口（`lis`）

**统一规则：每次上报完成后，设备保持可接收状态 `lis` 秒，默认 3 秒。**

| 链路   | 窗口行为                             |
| ---- | -------------------------------- |
| TCP  | 上报后不关连接，`lis` 秒内收到一包即处理，处理完关闭连接  |
| UDP  | socket 保持 `lis` 秒，取第一包，其余丢弃      |
| MQTT | 订阅常驻，窗口外也能收；`lis` 仅约束「发布后等回执」的时长 |

```
AT+LIS=3      # 默认，上报后监听 3 s
AT+LIS=10     # 平台响应慢 / 现场 RTT 大，放宽
AT+LIS=0      # 不留窗口，纯单向上报（最省电，配置只能下次窗口再发）
```

- 取值范围 `1~30`，越界回 `ERROR`；`0` 表示关闭。
- **立即生效**，改完下一个上报周期就按新值走，不用重启。
- 平台侧下发时机：收到数据包后**立刻**回配置，延迟必须小于 `lis`，否则设备已关窗口。
- 电池型设备建议 `lis=3`；市电型可放到 `lis=5~10` 容忍抖动。

## 5.3 配置包格式

```json
{"cfg_v":1,"per":"60,300","thre":"8000,-2000"}
```

| 字段     | 必填 | 说明                                      |
| ------ | -- | --------------------------------------- |
| `cfg_v` | 是  | **配置版本号**，整数 `1~255`，与 `AT+CFG_V` 同一个 key。既标识「这是配置包」（缺了就当普通数据回包丢弃），也用于版本追踪：设备写入后自动 +1 |
| `tt`   | 否  | Unix 秒，带此字段即触发校时                        |
| 其余 key | 否  | 与 AT 同名，值为**字符串**，内容等于 `AT+KEY=` 后面那一整段 |

规则：

1. `cfg_v` 是通用型 key，也是**包控制字段**：包里必须有它，缺了整包丢弃。它是**唯一用数字**的字段（不加引号），其余 key 一律字符串。
2. 只带要改的字段，未出现的 key 保持原值。
3. 值一律用字符串，段串原样抄 AT 的写法（`"thre":"OFF"`、`"unit":"1"`、`"per":"60,300"`）。
4. 单包 ≤ 512 B（设备 1 KB 缓冲），超长丢弃。
5. 一个包可以同时带配置和 `tt`，先校时再写配置。

> `cfg_v` 填**最近一次上报里的值**即可：设备只据此识别「这是配置包」，不做相等校验；写入成功后才 +1。

> 本节的 JSON 包体用于 **TCP / UDP / MQTT**。

**AT 与远程的对应关系**

| AT 写法           | 远程 JSON          | 说明            |
| --------------- | ---------------- | ------------- |
| `AT+PER=60,300` | `"per":"60,300"` | 段串原样          |
| `AT+THRE=OFF`   | `"thre":"OFF"`   | 关键字也原样        |
| `AT+UNIT=1`     | `"unit":"1"`     | 单值也是字符串       |
| `AT+ACK=1`      | `"ack":"1"`      | —             |
| `AT+VER=...`    | —                | **只读，不支持远程写** |

## 5.4 处理时序与应答

```
设备                                 平台
 │  ① 上报数据包（evt=0/1/3…）        │
 ├───────────────────────────────────>│
 │                                    │
 │  ② lis 窗口内回配置 JSON            │
 │<───────────────────────────────────┤
 │                                    │
 │  ③ 校验 cfg_v → 逐 key 写入 → 落盘  │
 │  ④ ack=1 时回一个字符 A             │
 ├───────────────────────────────────>│
 │  ⑤ 关闭窗口 / 断开                 │
```

| 情况               | 设备处理                                | 回执                  |
| ---------------- | ----------------------------------- | ------------------- |
| 正常               | 逐 key 落盘 `UserCfg`                  | `ack=1` 时回 `A`，否则静默 |
| 含 `tt`           | 先校时，再写其余 key                        | 同上                  |
| 未知 key           | 忽略该项，其余照写                           | 照发                  |
| 值越界 / 段数不符       | **该 key 忽略**，其余照写，`AT+LOG=1` 时串口打一行 | 照发                  |
| 非 JSON / 超 512 B | 整包丢弃                                | 不回                  |
| `cfg_v` 缺失       | 整包丢弃（无版本号，不当作配置包）                    | 不回                  |
| `cfg_v` 越界       | 不在 `1~255`（含 `0`、非整数）→ 整包丢弃          | 不回                  |
| 窗口内无包            | 正常超时，关窗口                            | —                   |

**为什么不回 JSON 回执**：4G 链路不做内容校验，收到任意字符即视为 OK（见 §2.1 `ack`）。平台以「设备下一包是否已带新配置」作为最终确认，比等回执可靠。

## 5.5 分类型下发示例

配置包只带该类能用的 key，跨类 key 会被忽略，下发前先看 `ATH` 清单。

**温湿度类**

```json
{"cfg_v":1,"per":"60,300","tun":"0","cal":"-30,150","thre":"8000,-2000","var":"50,200"}
```

**IO 类**（`thre` 必须显式 `OFF`）

```json
{"cfg_v":1,"per":"60,3600","thre":"OFF","var":"1,1"}
```

**气体类**

```json
{"cfg_v":1,"cal":"-50","thre":"1000,400","var":"50","per":"60,600"}
```

**运动类**

```json
{"cfg_v":1,"thre":"300,0","var":"50","cal":"0,0,-20","per":"60,3600"}
```

**压力类**

```json
{"cfg_v":1,"unit":"1","ran":"0,2500","cal":"1,-120","thre":"2500,0","per":"60,300"}
```

液位子型把 `unit` 换 `5`、`ran` 换 `0,5`；温压一体再加 `"tun":"0"` 和四段 `thre`：

```json
{"cfg_v":1,"unit":"1","ran":"0,2500","tun":"0","cal":"1,-120,-30","thre":"8000,-2000,2500,0"}
```

**计量计数类（采集器）**

```json
{"cfg_v":1,"cal":"0,20,0","var":"100,50,50","pwr":"2,1","dly":"3","per":"30,300"}
```

**控制类**

```json
{"cfg_v":1,"omd":"2","pls":"500","io":"1"}
```

**网关类**

```json
{"cfg_v":1,"server":"TCP,81.71.164.182,20004","per":"60,600","lis":"5"}
```

## 5.6 平台侧对接要点

| 链路       | 要点                                                                                                         |
| -------- | ---------------------------------------------------------------------------------------------------------- |
| **TCP**  | ① 一包 JSON **以 `\n` 结尾**，设备按行收，避免粘包；② 收到数据包后立即在同连接回写，不要另起连接；③ 回写完由平台主动关，或设备按 `lis` 超时关                      |
| **UDP**  | ① 单包 ≤ 512 B，**不要分片**；② 目标端口与设备上报源端口一致；③ 无重传，丢了就等下个周期                                                      |
| **MQTT** | ① 设备订阅 `pub/sub` 第 5 段，平台往该 topic 发布；② QoS 建议 `1`，`retain=0`（**不要 retain**，否则重连会重放旧配置）；③ 设备上线后先订阅再上报，顺序不能反 |

**主题命名建议**

```
上行：wwiot/{model}/{sn}/up
下行：wwiot/{model}/{sn}/dw      ← 平台发布，设备订阅
```

对应配置：

```
AT+MQTT=user,pass,{sn},wwiot/WW75C/24090007/up/wwiot/WW75C/24090007/dw
```

> 下行主题后缀固定为 `dw`（downlink write）。`up` / `dw` 只用于 MQTT 主题；JSON 包内的 `cfg_v` 是**配置版本号 key**，两者无关，不要混用。
>
> 主题里的 `{model}` **只取型号段**（`model` 字段逗号前的部分），不含固件版本；`model` 字段值是 `WW75C,2.0.3` 时，主题仍写 `wwiot/WW75C/24090007/up`。

**主题长度上限 48 字符**

发布与订阅**各自单独计**，`/` 和层级都算 1 字符，按 UTF-8 字节算：

| 项             | 长度            |
| ------------- | ------------- |
| `wwiot/`      | 6             |
| `{model}`     | 5（`WW75C`）    |
| `/`           | 1             |
| `{sn}`        | 8（`24090007`） |
| `/up` 或 `/dw` | 3             |
| **合计**        | **23**        |

按 `wwiot/{model}/{sn}/up`（或 `/dw`）命名，留给 `model` + `sn` 的总预算是 **39 字符**（48 − 6 − 3）。超限的处理：


- AT 写入：`AT+MQTT` 回 `ERROR`，**原配置不变**，不截断、不自动补全。
- 远程下发：整包含 `mqtt` 时该 key 丢弃，其余 key 照常写入，回 `A` 但不代表 `mqtt` 成功——平台需在下个周期读 `AT+MQTT?` 复核。
- 现有 `sn` 为 8~14 位，`model` ≤ 8 字符，常规命名都在预算内；客户自定义长主题时按上表先算长度。

**下发时机**：必须在收到数据包后的 `lis` 秒内发出。链路 RTT 大的现场把 `lis` 加大到 5~10，或改用 MQTT（订阅常驻，不受窗口限制）。

## 5.7 LoRa 链路（见分册）

LoRa / LoRaWAN 远程配置（编号+AT 文本帧、LoRaWAN 下行功能码、私有寄存器）已拆至 **[《AT & 远程配置指导手册（LoRa）》](./at-remote-config-lora.md)**，本 4G 分册不再展开。

## 5.8 配置生效时机

远程写入与 AT 写入的生效规则完全一致，见各 key 的「生效」列：

| 生效 | key | 现场表现 |
|---|---|---|
| 立即 | `cal` `ack` `log` `rst` `lis` `io` `omd` `pls` `unit` `ran` | 下一包数据就是新值 |
| 下周期 | `per` `var` `thre` `tun` `pwr` | 等一个采样周期后才体现 |
| 重连 | `server` `mqtt` `apn` | 不断链不生效，需要 `AT+RST` 或等重连 |
| 重启 | `ver`、`dly`（采集器） | 必须重启，远程下发后不会立即变 |

> 远程改 `server` 是高风险操作：设备按新地址重连后可能直接失联。建议平台侧对 `server` `apn` `mqtt` 三个 key 加二次确认，并在下发前记录原值。

## 6 上报报文

> **`bat` 口径（V4.4）**：原电量百分比与电池电压毫伏两个独立字段已合并为**一个字符串字段** `bat`，两段英文逗号。写法示例 `bat=98,3200` → JSON **`"bat":"98,3200"`**（第 1 段=电量百分比 0~100，第 2 段=电池电压毫伏；`3200` 即 3.2 V）。外接供电/无电池可用 `"bat":"0,0"`。
>
> **配置快照口径（V4.5）**：注册包里的配置项与 AT / 远程下发**同名同值格式**，多段仍用英文逗号写在**一个**字符串里，例如 `"per":"60,600"`、`"thre":"8000,-2000"`（或 `"OFF"`）、`"server":"TCP,81.71.164.182,20004"`。**不要**拆成 `per_d`/`per_r`、`thre_hi`/`thre_lo`、`srv`/`host`/`port`。

### 6.1 注册包（`evt=10`，联网后首包）

字段：`no` `model`（`型号,固件版本`）`iccid` `imei` `csq` `bat` `ts`  
另带当前**配置快照**（与 AT / 远程 JSON **同名同口径、不拆段**）：`per`（`检测秒,上报秒`）、`thre`（`上限,下限` 或 `OFF`）、`server`（`类型,主机,端口`）；需要时还可带同口径的其它配置 key（如 `cfg_v` `var` `unit` `ran` `mqtt` `apn`）。以及**本型测量快照**（与状态包相同的传感器 key，见 §6.3.0）。

`no` `seq` `ok` `model`（`型号,固件版本`）`evt` `csq` `bat` `ts` + **本型数据 key**（见 §6.3）

总示例（温压一体，预警）：

```json
{"no":"WW75C24090007","model":"WW75C,2.0.3","seq":452,"evt":3,"ok":1,
 "t":2350,"p":48520,"u":1,"bat":"76,3005","csq":18,"ts":1793970120}

### 6.3 分类型数据 key

数据包在公共字段之外，只带**本型**测量字段（下表）。`ok=0` 时本型字段可省略。

**兼容**：部分现网固件（WW105C / WW25C / WW73C 等产品手册）仍发两位小数浮点（如 `"t":29.10`）；平台应同时接受整型与浮点，**新固件以本表整型为准**。

#### 6.3.1 速查

| 类型 | 本型 key | 缩放 / 取值 | 代表型号 |
|---|---|---|---|
| 温湿度（单路） | `t` `rh` | 0.01 ℃ / 0.01 %RH | WW-10C / 11C / 12C |
| 多点温湿度 | `t1` `rh1` `t2` `rh2` … | 同上；通道从 1 起，段序同 `var`/`thre` | 多探头温湿度款 |
| 纯温度多点 | `t1` `t2` … | 0.01 ℃ | 测温杆等多路纯温 |
| 热电偶 | `t` `tc` | 热端 / 冷端，均为 0.01 ℃ | WW-15C-K |
| 门磁（单路） | `door` | `0` 关闭 / `1` 打开 | WW-27C |
| 双门磁 | `door` | 位图：`0` 关闭；`1` 左门开；`3` 左右门开（bit0=左，bit1=右） | **WW-27C-D** |
| 水浸 | `water` | `0` 无水 / `1` 有水 | WW-20C / 26C |
| 其它开关量 | `d` 或 `d1` `d2` …；人体 `pir` | `0`/`1` | 烟感 / SOS / WW-21C 等 |
| **人体存在 / 跌倒多传感** | `t` `rh` `lux` `pir` `pres` `fall` `stay` `mot` `mlvl` | `t`/`rh`=0.01；`lux`=光照；`pir`/`pres`/`fall`/`stay`=`0`/`1`；`mot`=字符串；`mlvl`=等级 | **WW-25C** |
| 气体 | `g`；补偿时另带 `t` `rh` | `g`=ppm | WW-30C |
| 倾角 | `x` `y` `z` | 0.01 ° | WW-50C |
| 振动 | `acc` | mg | WW-51C |
| 压力 | `p` `u` | `p`=0.01×当前 UNIT 显示值；`u`=UNIT 枚举 | WW-70C |
| 温压一体 | `t` `p` `u` | 温度 0.01 ℃ + 压力同上 | WW-71C-P1 / 75C |

| 拉力 | `p` `u` | 同压力 | WW-78C |
| 电压/电流/功率 | `v` `i` `w` | 0.01 V / 0.01 A / 0.01 W（功率不用 `p`，避与压力冲突） | WW-60 / 61C |

### 6.4 报文字段长度

上行报文的字符串字段与配置侧同口径（§1.1），平台按此建表字段宽度：

| 字段 | 上限 | 超限 | 字段 | 上限 | 超限 |
|---|---|---|---|---|---|
| `no` | 16 | 整包拒收 | `server` | 同 `AT+SERVER`（类型≤8 + 主机≤64 + 端口） | 整包拒收 |
| `model` | 20 | 整包拒收 | `per` / `thre` / `bat` | 同配置多段字符串 | 整包拒收 |
| `iccid` | 20 | 不足不补零 | `imei` | 15 | 不足不补零 |
| `mod` | 16 | 截断前 16 | `mqtt` / `apn` | 同配置多段字符串 | 整包拒收 |

整包上限 512 B；超过 512 B 设备侧不发，改为分包（大包场景仅 OTA 与补传批量上报，走 `evt=6`）。

## 7 兼容与迁移

| 项 | 说明 |
|---|---|
| 旧固件（固件 2.0.x） | 只认 `per var unit ran thre server mqtt ver log rst tt` 11 个 key，其余回 `ERROR` |
| 新固件 | 22 个 key（14 通用型 + 8 专属），`ATH` 清单为准入依据 |
| `ver` 段数 | 现行 2 段 `型号,固件版本`；旧固件可能回 3 段（含硬件版本），平台只取前两段 |
| `thre` 温压一体 | 2 段（旧，仅温度）/ 4 段（新），按固件版本（`model` 第 2 段）判断 |
| `var` 多段 | 单路设备仍只写一段，行为与旧固件一致 |
| 未知 key | 一律 `ERROR`；不引入 `ERR<n>` 细分码，避免固件分支 |

## 8 自检脚本

```
+++
AT
ATH                 # 先看这台机器支持哪些指令，与手册逐行对账
AT+VER?
AT+PER?
AT+VAR?
AT+THRE?
AT+CFG_V?
AT+UNIT?
AT+RAN?
AT+SERVER?
AT+MQTT?
