2上行报文

报文为单行 JSON + \n。用字段 evt 区分类型（无 reason 字段）。

evt名称何时发送
10REG 注册开机联网成功后；断网恢复需重新注册时
0PER 周期运动：按 per_d；静止：按 per_r；仅发状态包
1IODI 变化并稳定 3s（上报冻结采样，避免磁铁离开后变成 0）
2FORCEAT+REPORT / 按键强制
3ADC运动中 VIN 有值→无值，带峰值/时长
4GPS运动中 GPS 良好时的分钟周期

2.6 字段说明

3下行通道（服务器 → 设备）

3.1 时机

设备每次上行发送成功后，保持当前会话约 3 秒（长连接）监听下行：

协议行为
UDP发完后不立刻关 socket，听 +MIPURC "rudp"；超时或处理完再关闭
TCP在已连接上听 +MIPURC "rtcp"
MQTT（出厂默认）听订阅主题下行，QoS=0

平台侧建议：

  1. 收到设备某一包上行后，在 3 秒内向同一地址/端口（UDP 时为设备源 IP/端口对应的对端会话）回发一包下行 JSON；
  2. 或在镜像本机 20000 时，对刚发来的设备源地址做 UDP 回包。
设备不是常驻监听端口，只有上报后的短窗口可收控制。若需更快响应，可缩短 AT+PER 周期，或触发 FORCE 上报。

3.2 下行 JSON 约定

项说明
编码UTF-8，建议单行，总长 ≤ 512 B（设备缓冲 1 KB）
键名不区分大小写（推荐小写 k1 / k2 / rly）
配置类 value字符串，格式与本地 AT+KEY= 右侧相同；也可用 "?" 查询
数字兼容log / rly / k1 / k2 可用数字或字符串
对时"tt": <unix秒>
落盘仅配置类 SET 成功后写 Flash；继电器控制不落盘

项值

5远程控制：2 路继电器

硬件：K1=PB10，K2=PB02（MCU 高电平吸合）。上报字段 rly 为位图。

5.1 推荐下发字段

方式 A：整路掩码 / 通道写法（与 AT+RLY 一致）

JSON效果
{"rly":"1,1"}K1 吸合
{"rly":"1,0"}K1 断开
{"rly":"2,1"}K2 吸合
{"rly":"2,0"}K2 断开
{"rly":"3"} 或 {"rly":3}K1+K2 同时吸合（mask=0b11）
{"rly":"0"} 或 {"rly":0}两路全断
{"rly":"1"}仅 K1（mask=0b01）
{"rly":"2"}仅 K2（mask=0b10）
{"rly":"?"}查询当前 mask，设备回 {"rly":"1"} 等

方式 B：独立开关（更直观）

{"k1":1,"k2":0} {"k1":0,"k2":1} {"k1":"?","k2":"?"}

数字与字符串均可：{"k1":1} 等价 {"k1":"1"}。

5.2 控制后设备行为

  1. 立即改变继电器输出（不写 Flash，掉电不保持）。
  2. 回执一包 JSON（含当前 rly / k1 / k2）。
  3. 置位强制上报，随后再发一包业务数据（evt=2 或周期包），其中 rly 反映新状态。

5.3 完整交互时序（UDP）

设备 ──UDP──► 平台 业务/注册 JSON（含当前 rly） 平台 ──UDP──► 设备 {"k1":1,"k2":0} （须在上报后 ~3s 内） 设备 ──UDP──► 平台 {"k1":"1","k2":"0"} （控制回执） 设备 ──UDP──► 平台 业务包 rly=1 （强制/周期确认）

5.4 本地 AT 对照（调试）

AT+RLY? → rly=0x01 K1=1 K2=0 AT+RLY=1,1 → K1 吸合 AT+RLY=2,0 → K2 断开 AT+RLY=3 → 两路吸合

6平台实现要点

  1. 监听设备上行端口（本项目默认 20000，可已镜像到本机）。
  2. 解析 no / evt / rly / di / moving 等。
  3. 需要控继电器时，在收到上行后 3 秒内向设备回发：推荐 {"k1":1,"k2":0} 或 {"rly":"1,1"}。
  4. 可选同时下发配置：{"per":"60,300","tt":1710000000}。
  5. 配置与控制可同包：{"k1":1,"per":"30,120"}。
  6. 以设备后续上行里的 rly 作为最终状态确认。
