1产品概述与快速上手

WWG3（对外型号 WW-G3 / WW-G0 系列）是面向物联网汇聚场景的边缘网关，支持：

  • 多网络接入：以太网（静态 / DHCP）、WiFi STA/AP、4G Cat.1
  • 数据转发：最多 4 路 TCP/UDP/MQTT/HTTP，格式 RAW / JSON / TLV
  • RS485 Modbus：输出（Slave，LoRa→寄存器）/ 输入（Master 轮询）
  • LoRa（可选）：烧录工厂设备 ID 后启用 SX1302 收发与转发
  • 管理入口：Web（端口 80）、USB AT（115200）、BLE NUS

1.1 上电步骤

  1. 接通电源，约 5～10 秒完成自检与联网初始化。
  2. 网线接电脑（本机设同网段，如 192.168.1.100），或按 WiFi 配置连接。
  3. 浏览器打开管理页（见下表）。
  4. USB-C：波特率 115200 8N1，可发 AT 并查看日志。
入口默认地址 / 参数
有线网口http://192.168.1.252/
WiFi 热点 APhttp://192.168.7.1/
USB 串口115200 8N1
Web 管理账号与初始密码以随箱配置卡 / 设备标签为准；首次登录后请立即修改默认密码。

3网络接入（以太网 / WiFi / 4G）

3.1 以太网

  • 默认静态见第 2 章；DHCP：PUT /api/eth {"dhcp":true} 或 AT+ETH=0,0。
  • 静态：AT+ETH=0,1,192.168.1.252,255.255.255.0,192.168.1.1,8.8.8.8。

3.2 WiFi

  • mode=0 为 AP，mode=1 为 STA。
  • AT：AT+WIFI=<mode>,<ap_ssid>,<ap_pwd>,<sta_ssid>,<sta_pwd>,<ch>（改后需重启）。
  • HTTP：PUT /api/wifi（见第 6 章）。

3.3 4G

  • 插 SIM 后自动搜网；GET /api/lte 或 AT+4G? 查看状态。
  • 透传：AT+4GAT=AT+CSQ。LTE state：0 关机 … 4 已注册 … 5 已联网。

3.4 LoRa（可选）

  • 必须已烧录工厂设备 ID（SN）才会初始化 SX1302。
  • 无 SN / 无射频时不影响 ETH / WiFi / 4G / RS485 / Web 功能。

4Web 管理与数据转发

  • 管理页：GET / 或 /index.html，端口 80。
  • 通道：最多 4 路；协议 0=TCP 1=UDP 2=MQTT 3=HTTP；格式 0=RAW 1=JSON 2=TLV。
  • 万维云默认通道见第 2 章；可在页面「数据通道」增删改。
  • OTA：POST /api/ota 上传 .bin（64KB～3MB），成功后设备重启。

5RS485 / Modbus 协议

5.1 两种工作模式

模式mode网关角色LoRa→寄存器上位机查询网关
输出0Slave是是（FC03/FC04）
输入（出厂默认）1Master否否（网关主动轮询外设）

串口参数默认 9600 8N1，从站号默认 1。查询传感器寄存器（温湿度等）必须使用「输出」模式。

5.2 设备列表与寄存器地址

对设备列表按 device_type 分组，同类型内按顺序分配 index=0,1,2,…（每类型最多 100，设备总数上限 32）：

slot = device_type * 100 + index base = slot * 10 寄存器地址 = base + offset // offset = 0..9
偏移字段类型含义
0batteryu16电量 %
1temperaturei16温度 ℃×10（有符号）
2humidityu16湿度 %RH
3adci16ADC
4voltagei16电压×10
5electricityi16电流类
6switchu16开关量
7oxygenu16氧浓度等
8luxu16光照（截断）
9sequ16报文序号低 16 位

温湿度节点常用偏移 0~2；缺字段保持 0xFFFF。地址示例：device_type=16、index=0 → base=16000（电量 16000 / 温度 16001 / 湿度 16002）。

5.3 LoRa 报文 → 寄存器

帧格式与 sensor_decode 一致：字节 0 为 version；1..4 为 device_no（拼成 8 位大写十六进制）；5 为 ctl；6..7 为 seq（大端，写入偏移 9）；8 起为 TLV 数据区（末 2 字节为链路 CRC）。相关 TLV：

Tag长度写入
0x002bat：(byte0&0x1F)/31×100 → 偏移 0；byte1&0x7F → device_type
0x042温度：i16 BE /10 → 再×10 存入偏移 1
0x051湿度 → 偏移 2
0x214精细温湿：temp/100、hum/10 → 偏移 1 / 2
0x032ADC → 偏移 3
0x061oxygen → 偏移 7

实测温湿度帧示例（CRC OK）：03 30 00 3E 2F 00 09 23 00 7F 10 04 01 10 05 34 1D 3E → device_no=30003E2F、device_type=16、电量 100、温度 272（27.2℃）、湿度 52，对应基址 16000。

5.4 上位机查询（输出模式 Slave）

支持 FC03 / FC04（同一镜像）。请求帧：[SlaveID][Func][StartHi][StartLo][QtyHi][QtyLo][CrcLo][CrcHi]，CRC16-Modbus（初值 0xFFFF、多项式 0xA001、低字节在前），Qty 1..64。应答帧：[SlaveID][Func][ByteCount][Data…]×Qty [CrcLo][CrcHi]，寄存器高字节在前，有符号值按 int16 大端解释。不落在任何槽位的地址返回 0xFFFF；非法功能码 / CRC 错误静默丢弃。

温湿度标准查询（先配置 mode=0 并登记设备白名单）：

PUT /api/rs485 { "enabled": true, "mode": 0, "slave_id": 1, "baud": 9600 } PUT /api/rs485/devices { "devices": [ { "enabled": true, "device_type": 16, "device_no": "30003E2F" } ] } 请求：01 03 3E 80 00 03 09 CB 应答：01 03 06 00 64 01 10 00 34 51 53 00 64 → 16000 = 100（电量%） 01 10 → 16001 = 272（27.2℃） 00 34 → 16002 = 52（湿度%）

5.5 配置检查清单与常见失败

  1. GET /api/rs485 → mode=0（输出）、enabled=true、ready=true。
  2. GET /api/rs485/devices → 含真实 device_no / device_type，确认 base_addr。
  3. GET /api/overview 或串口 LORA # → rx_crc_ok 在增长。
  4. GET /api/lora/rxlog → 核对 hex 中 device_no / type 与白名单一致。
  5. RS485 主站：9600 8N1，从站号与 slave_id 一致，发 FC03。
现象原因
一直 0xFFFF白名单 device_no/type 与实包不一致；或尚未收到 LoRa
无应答仍是输入模式；波特率 / 接线 / 从站号错误；CRC 错被丢弃
温度离谱按 ℃×10 解释；有符号 int16

5.6 输入模式（Master 轮询）

mode=1 时网关不把 LoRa 写入寄存器，而是按 /api/rs485/polls 主动读外设（字段：slave_id、func 3/4、start_addr / quantity≤32、interval_ms 最小 200ms、enabled；最多 8 条轮询）。成功读到的完整应答帧（含 CRC）经 channel_broadcast 转发到数据通道。

7AT 命令

7.1 命令通道与模式

  • USB Serial/JTAG（推荐）：USB-C（IO19/IO20），115200 8N1，Putty / TeraTerm / 串口调试助手均可。
  • BLE SPP (NUS)：Nordic UART Service（UUID 6E400001-B5A3-F393-E0A9-E50E24DCCA9E），设备名 WWG3_XXXX（XXXX 为 SN 后 4 位），无配对密码。
  • 两通道互不干扰可同时使用；串口 UART0 仅输出日志，不接受 AT 输入。
  • 上电默认即 AT 命令模式；ATO 退出并上锁，+++（带回车）重新进入——已设 SER 密码时返回 OK.SER，需 AT+SER=<密码> 认证，错误返回 ERR2。

8GW 网关 TLV 协议

8.1 帧结构（第一层 Frame）

字段长度说明
Delimiter5固定 ASCII "start"（73 74 61 72 74）
Version10=V0（废弃）、1=V1 … 5=V5
Length2 (u16)除 Delimiter 外的总长度（含 GatewayID、Data、CRC）
GatewayID8网关 ID
DataNTLV1 数据项，可多个自由组合
CRC2CRC16，计算范围 Version → Data 末尾

流式解析：遇到 "start" 开始按帧解析，用 Length + CRC 校验完整性，通过后继续扫描下一帧（天然支持粘包）。

8.2 TLV 层级

TLV1 Type名称Value 内容
0x00GW_UP_STATUS网关状态包（心跳），内部为 TLV2：0x00 Info（2B）、0x01 CCID（20B）、0x02 Location（2×float32 经纬度）
0x01GW_UP_DATA终端上行数据：0x00 RF_CHAIN、0x01 FREQUENCY、0x02 MODULATION、0x03 CRC_STATUS、0x04 SF、0x05 CODE_RATE、0x06 RSSI、0x07 SNR（0.1dB）、0x08 RF_DATA（带 Length 的终端原始数据）、0x09 TMST、0x0A IS_CACHE
0x02GW_UP_OTAOTA / 文件传输：0x00~0x03 OTA_REQ/ACK/DATA/DATA_ACK；0x10~0x13 FILE 系列（结构相同）
0x03~0xFFRFU保留，按 Length 跳过

TLV1 编码：Type(uint8) + Length(uint16) + Value；GW_UP_DATA 中除 RF_DATA 外的项为固定长度仅传 Type + Value。解析器必须按 Type 逐项解析、支持字段缺失与未知类型跳过（前向兼容）。SF 编码：V3+ 直接用数字 5~12，旧版本 0x40=SF12；V4 中 FREQUENCY 字段用作频偏；V5+ 新增 TMST 与 IS_CACHE（≥1 为离线缓存数据）。

9固件烧录与设备 ID

9.1 SN 规则

项要求
格式恰好 16 个十六进制字符（8 字节），字符集 0-9 / A-F
示例0001006400000001
存储NVS 命名空间 loragw_factory，键 sn；不受配置重置 / 出厂恢复影响
生效写入后需重启，LoRa 才会初始化；整片擦除（erase-flash）会清空 SN

9.2 固件烧录（ESP-IDF）

  • 芯片目标 ESP32-S3，工具链 ESP-IDF v5.x，USB 板载 Serial/JTAG。
  • 16MB Flash 双 OTA 分区：ota_0 0x20000（3MB）、ota_1 0x320000（3MB）；工厂 SN 在 NVS，与 app 分区无关。
  • 编译烧录：idf.py set-target esp32s3 && idf.py build && idf.py -p COMx flash；开发迭代可 idf.py -p COMx app-flash。
  • 量产脚本可用 esptool 按地址烧录（bootloader 0x0 / 分区表 0x8000 / app 0x20000），或使用 release/WWG3_vX.Y.Z_flash 全量烧录包。
  • 已联网设备 OTA：curl -X POST http://<设备IP>/api/ota --data-binary @build/esp32-loragw.bin，OTA 不清除工厂 SN。

9.3 烧录设备 ID（工厂 SN）

产线推荐流程：先烧固件 → 再写 SN → 重启 → 确认 LoRa 已启用。

方式操作
A：BLE AT（推荐）连接 WWG3_XXXX，发送 AT+SN=0001006400000001（期望 OK + +SN: saved），AT+RSTC 重启后 AT+SN? / AT+INFO? 校验（应见 DeviceID: 0001006400000001）
B：HTTP设备 AP（192.168.7.1）或 STA/ETH IP：PUT /api/sn {"sn":"0001006400000001"}，必须写满 16 hex，成功后重启
C：产测脚本批量烧固件 → 联网 → PUT /api/sn → 重启 → GET /api/overview 核对 device_id 与标签一致

9.4 验收检查清单

步骤期望
烧固件后未写 SNWeb 设备 ID 为 --；LoRa 未初始化（日志提示 Factory SN NOT SET）
仅写入 8 hex（如 00000001）无效，设备不认
AT+SN= / PUT /api/sn保存成功
