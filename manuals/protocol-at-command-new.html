产品型号 WW-D5-L；固件版本见 AT+VER? / AT+INFO? 中的「固件（FW）」（当前 1.5.0）。功能定位：RS485 Modbus 采集 → LoRa 私有网 TLV 转发（无 4G、无 JSON 上报）。

5常用指令说明

5.1 AT+VER

AT+VER? → AT+VER=WW-D5-L,1.0 → OK

开机仍以固件内置型号覆盖显示字段。

5.2 AT+INFO?（纯文本）

字段名格式：中文（KEY）=值（UTF-8）。查询/设置指令本身仍用英文 KEY（如 AT+PER?）。

设备号（NO）=... 型号（MODEL）=WW-D5-L 产品版本（PVER）=1.0 固件（FW）=1.5.0 模组（MOD）=WW-D5-L 电池电压（BAT_MV）=... 电量（BAT）=... 射频类型（RADIO）=lora 频率（FREQ）=470500000 扩频因子（SF）=7 网络号（NETID）=0x5A 发射IQ（IQ_TX）=0 接收IQ（IQ_RX）=1 LoRa就绪（LORA）=1 日志（LOG）=0 周期（PER）=10,20 供电（PWR）=3,1 RS485波特率（MB_BAUD）=9600 采集模式（MB_MODE）=0 OK

ATH / AT+H? 列表同样带中文名，例如：周期（PER） AT+PER?。

5.3 AT+DATA?

首行 Modbus 配置摘要，次行注册帧 TLV 十六进制（便于对照空口）。

5.4 AT+LORA

AT+LORA=txHz,txSF,rxHz,rxSF,netId,pwr[,hop,bwHz,preamble,iqTx,iqRx,pollMs,chN,stepHz,cr] AT+LORA=470500000,7,500500000,7,0x5A,22

设置后立即装入射频并落盘。

5.5 RS485 / Modbus

AT+MBUART=9600,0,1 # parity: 0=N 1=E 2=O（当前硬件按 8N1） AT+MBMODE=0 AT+MBCMD=0,1,1,0x03,0,2 # idx,en,slave,fc,reg,qty AT+MBSCAN=1,1,10,0x03,0,1 # en,start,end,fc,reg,qty AT+MBRAW=010300000002C40B # 整帧 RTU hex（含 CRC）透传
  • 固定指令最多 10 条（idx 0~9）
  • 地址轮询按 start~end 循环，不限制条数
  • 采集节奏由 AT+PER 发送秒驱动；AT+PER=0,0 关闭周期
  • 单次应答超时固定 500 ms（APP_MB_TIMEOUT_MS）
  • 采集/透传成功经 LoRa 上报 TLV 0x24（TLV_TYPE_MODBUS）

指令示例说明
PERAT+PER=10,20配置 检测,发送（秒）；本产品不跑检测，按 20s 发送周期供电采集

6串口 OTA（固件升级）

口：LPUART0（调试 USB）115200 8N1，原始字节流（二进制帧 + 少量 ASCII AT/ACK）。开关：APP_OTA_ENABLE=1。禁止 LoRa 远程 AT+OTA（ERR8）。

6.1 总流程（状态机）

业务运行中 --+++ / AT(+SER)--> AT 命令态 | AT+OTA=1 v OTA armed（停上报；等 start 帧） | BEGIN(0x10) v 擦下载区（数秒；成功后 ACK） | DATA(0x02) × N v 写固件B块（每块 ACK；末块后 commit） | 写 UpdateParam + 复位 v Boot 拷贝 A←B（串口可能断开/无输出） v 新 App 启动（再 AT+INFO? 验 fw）
阶段Host → DeviceDevice → Host
进命令态+++ 然后可选 AT\r\n / AT+SER=pwd\r\nOK / OK.SER / ERR*
武装AT+OTA=1\r\nAT+FW=<ver>\r\n + OK\r\n
固件信息1 帧 BEGIN：romsize + 整包 md5ACK tag=0x10
固件正文N 帧 DATA：每帧最多 256B 数据每帧 ACK tag=0x02
收尾（末块成功后设备自行复位）可能无 ACK（已复位）；再等启动日志

一句话：AT+OTA=1 之后先发固件信息帧（BEGIN），再按 256 字节/块发固件数据帧（DATA）；不是把 .bin 裸流直灌。

6.3 AT 文本阶段（武装）

行结束：\r\n。

Host: +++ Host: AT\r\n Dev: OK\r\n # 若设备有密码： Host: AT+SER=<pwd>\r\n Dev: OK\r\n Host: AT+OTA=1\r\n Dev: AT+FW=1.5.0\r\n Dev: OK\r\n

此后不要再发文本 AT（除非失败重来），改为发二进制帧。武装后 ota_hl19_busy()=1，主循环停周期上报。

6.4 二进制帧格式（Host → Device）

所有多字节整数均为小端 LE。推荐 ver=2。

6.4.1 外层封装（每帧相同）

偏移长度字段值 / 说明
05magicASCII start（73 74 61 72 74）
51ver建议 0x02
62inner_lenLE u16 = 整帧长度 - 5（即从 ver 起的字节数）
86markASCII %]CLQ[
141type固定 0x02
15…TLV长度 = inner_len - 10

约束（设备校验失败则丢弃、不回 ACK）：inner_len == len(frame) - 5；frame[8:14] == b"%]CLQ["；frame[14] == 0x02；整帧 ≥ 18 字节。

tlv = <见 BEGIN / DATA> inner = [ver] + le16(1+2+6+1+len(tlv)) + b"%]CLQ[" + [0x02] + tlv # 即 inner_len = 10 + len(tlv) frame = b"start" + inner

6.4.3 BEGIN（固件信息，tag = 0x10）

AT+OTA=1 之后，第一帧二进制必须是 BEGIN：romsize 为整包 App 固件字节数；md5 为对整个 app.bin 的 16 字节原始摘要。不要在 BEGIN 里带固件正文。

import hashlib with open("WW-D5-L_yyyyMMdd_app.bin", "rb") as f: firmware = f.read() romsize = len(firmware) # 例: 50000 assert 1 <= romsize <= 100 * 1024 md5 = hashlib.md5(firmware).digest() # 恰好 16 字节
偏移（相对 tag）长度字段值
01tag0x10
14romsizeLE u32
516md516 字节二进制
body = [0x10] + le32(romsize) + md5[0..15] tlv = le16(21) + body # payload_len = 21 # 整帧布局（ver=2）：inner_len = 33，整帧 = 38 字节 # 偏移 0 5 73 74 61 72 74 ASCII start # 偏移 5 1 02 ver # 偏移 6 2 21 00 inner_len=33（LE） # 偏移 8 6 25 5D 43 4C 51 5B ASCII %]CLQ[ # 偏移 14 1 02 type # 偏移 15 2 15 00 TLV payload_len=21（LE） # 偏移 17 1 10 tag = BEGIN # 偏移 18 4 romsize LE 例 50000 → 50 C3 00 00 # 偏移 22 16 md5 digest
import struct, hashlib def le16(v): return struct.pack("<H", v & 0xFFFF) def le32(v): return struct.pack("<I", v & 0xFFFFFFFF) OTA_MARK = b"%]CLQ[" ver = 2 body = bytes([0x10]) + le32(romsize) + md5 # 21B tlv = le16(len(body)) + body # 2+21 inner_len = 1 + 2 + len(OTA_MARK) + 1 + len(tlv) # = 33 inner = bytes([ver]) + le16(inner_len) + OTA_MARK + bytes([0x02]) + tlv frame = b"start" + inner # 38B

发送与应答：Host 一次 write 发完 38 字节；设备擦除下载区（可能数秒～数十秒）后回 %]CMY 10 01 \r\n（9 字节，01=成功）。

步骤要求
时机必须在 AT+OTA=1 的 OK 之后、任何 DATA 之前
次数整个升级过程只发 1 次 BEGIN（失败可整帧重发，最多建议 3 次）
超时等 ACK 30～45 s（擦 Flash）
成功收到 %]CMY + 0x10 + 0x01 + \r\n
失败ok≠1 或超时 → 勿发 DATA；重新 AT+OTA=1 再 BEGIN

6.4.4 DATA（固件正文，tag = 0x02）

字段长度说明
tag10x02
block2LE u16，从 1 起
block_dup2必须与 block 相同
dataN本块固件字节
psize = 256 block = 1 offset = 0 while offset < romsize: chunk = firmware[offset : offset + psize] # 末块可 < 256 body = [0x02] + le16(block) + le16(block) + chunk tlv = le16(len(body)) + body frame = wrap_start(tlv) # 同外层封装 send(frame) wait ACK tag=0x02 ok=1 offset += len(chunk) block += 1
项值
推荐每块256 字节
块号1, 2, 3, …
Flash 地址0x20000 + (block-1)*256
末块剩余不足 256 则发短包
写完条件设备侧累计 written ≥ romsize → 写 UpdateParam → 自动复位

约束：block ≥ 1，1 ≤ N ≤ 512；首块 N 锁定后续满包 psize，之后满包须同长，末包可短。满 256B 数据时整帧 278 字节。

6.5 ACK 格式（Device → Host）

设备处理完一帧后回定长 ASCII+二进制混排（无 start）：

偏移长度字段值
05markASCII %]CMY
51tag与请求 tag 相同（0x10 / 0x02）
61ok1 = 成功；其它 = 失败
72行尾\r\n（0x0D 0x0A）

共 9 字节。失败时 ok 含义（DATA 路径）：1 成功；2 帧损坏 / 双序号不一致 / block 非法；3 地址越界；4 Flash 写失败；5 chunk 大于锁定的 psize。中间可能夹杂 UTF-8 日志，工具应流式扫描 ACK 标记。

步骤建议

项值

9休眠与功耗

目标静态电流约 15 µA（电池、无 USB、射频冷睡、空中听关）。

9.1 软件已关断（DeepSleep 前）

9.2 测电流步骤

对照 A（MCU 仍醒，只关外设）——判断 6 mA 是否来自 LoRa/串口/485/外供：

AT+AIRLISTEN=0 AT+BUSOFF

看到 step4 … measure NOW 与 OK 后立刻拔 USB/J-Link，读 VBAT：

读数含义
明显下降（如降到 1～3 mA）先前主要是 LoRa/串口等；再复位后用 AT+SLEEP=20 测深睡
几乎不变仍 ≈6 mA电流不在这四路上：MCU 未睡、CH340 常挂 3V3、或其它硬件

对照 B（DeepSleep）：

AT+AIRLISTEN=0 AT+PER=0,0 AT+SLEEP=20

AT+SLEEP 会先 BUSOFF（NRST=0 等），再等 3 s 拔线，然后进深睡。醒后串口恢复，打印 WOKE slept=…（应接近 20000）。

9.3 仍是数 mA 时怎么看

读数常见原因
4～8 mA 且插着 USBCH340 工作电流；必须拔 Type-C 再测
~1～2 mA 且已拔 USBMAX3485 接在常电 3V3-MCU 上，接收机无法关（DE/#RE 短接）。硬件下限，软件关不掉
~4～6 mA 且已拔 USB、无空中听旧固件常见：SX1268 停在 RX（≈4.2 mA）+ MAX3485。新固件 DeepSleep 拉低 NRST
空中听=1每秒 RX 900ms，平均数 mA～十几 mA，正常
插着 J-LinkSWD 也会加电流

11LoRa 下发帧与 Demo

下发不使用 TLV。空口载荷即为 Modbus 风格写/读帧 + 系统 CRC16-XMODEM（tlv_cal_crc16 / cal_crc16，不是 Modbus CRC）。

11.1 帧格式

写多个保持寄存器（FC=0x10）: DevAddr(4 BE) | 0x10 | StartReg(2 BE) | RegN(2 BE) | ByteCount(1) | Data(2×RegN BE) | CRC16(2 BE) 读保持寄存器（FC=0x03）: DevAddr(4) | 0x03 | StartReg(2) | RegN(2) | CRC16(2) 应答（点对点）: 写应答: DevAddr | 0x10 | StartReg | RegN | CRC16 读应答: DevAddr | 0x03 | ByteCount | Data… | CRC16

DevAddr 为设备编号；广播使用 FF FF FF FF（编号不含 F 广播位）。ByteCount 必须 = 2 × RegN。CRC16 覆盖 DevAddr～Data 末，大端附加。Demo 默认设备编号 12 34 56 78。

12.6 推荐现场配置流程

1. 接串口，115200，上电 30s AT 窗内： AT AT+VER? AT+UNIT=2 AT+RAN=0,1.6 AT+PER=60,600 AT+THRE=160,0 # 按现场告警限修改 AT+BATT=28,42 # 按电池化学体系修改 AT+ZERO # 空压或现场零点 2. AT+DATA? / AT+REPORT 确认采样与发包 3. 拔掉 USB，装机上线；网关侧核对 NetID/频点/SF 4. 需要远程改参：走 LoRa 写寄存器

13WW105C 产品说明（4G 温湿度）

型号 WW105C；产品版本 200（固件内置，开机覆盖 Flash）；固件号见 AT+INFO? 的 fw，与产品版本独立。

13.1 产品定位

电池供电温湿度终端（MCU HC32L196 + ML307R 4G + CH9141 BLE + 段码 LCD + SHT40）：

  • 短时唤醒采样 / 上报，其余时间关 4G、MCU Sleep
  • 霍尔磁开关（PF05）短触立即上报、长按开关机
  • 开机 BLE 配置窗；调试口与 BLE 共 UART
  • 本地 AT 与 4G 远程 JSON 配置同源格式

13.2 运行逻辑

状态说明
OFF软关机：不采样不上报；LCD/背光关；红灯亮 5s 后灭
BLE_WIN开机后 BLE 等待连接，最长 20s
ACTIVE采样 / 判据 / 开 4G 上报

开机流程：初始化 GPIO / 日志 / UserCfg / 霍尔 / BLE / LCD / 电池 ADC（此时 4G 关）→ 软开机进入 BLE 窗 20s（绿灯闪）→ 窗内可处理 AT、霍尔 → 窗结束按是否已连接决定是否保持 BLE → 采温湿度 → 开 4G → 发注册包 evt=10 → 关 4G → 进入检测/上报休眠循环。冷复位默认开机（便于产测）。

霍尔键（PF05）

硬件：无磁=高，靠近=低；SysTick 1ms 采样；GPIO 双边沿中断仅用于唤醒 Sleep。

手势条件动作
短触靠近稳定 ≥ 30ms（靠近即触发，不必等离开）立即绿闪 + 请求上报 evt=2
长按靠近保持 ≥ 5s软开关机（覆盖未处理的短触）

感应到短触后绿灯持续闪烁，直到本次上报结束（成功熄灭回空闲 / 失败红闪 3 次）。关机后须先离开磁铁，再长按 5s 才能开机（防粘键）。

检测周期与上报周期

配置：AT+PER=<检测秒>,<上报秒> → detect_ms / report_ms。

触发行为
检测到期读 SHT40；先判阈值 → 再判变化量；均未命中则不开 4G
上报到期开 4G，发心跳 evt=0
霍尔 / AT+REPORT开 4G，发 evt=2

判据（相对上次成功上报的温湿度基准）：阈值使能且温度越限 → evt=3（优先）；否则 |ΔT|≥VAR温 或 |ΔRH|≥VAR湿 → evt=1；否则不上报，仅推进检测计时。周期锚点在开始上报前刷新计时，使服务器侧收到间隔更规律。

上报与 4G：关 4G 稳压后采电池刷 LCD 电量 → 绿灯闪 → 冷启动 4G / 驻网 → 若仍需注册则强制 evt=10 → TCP/MQTT 发送 JSON → TCP 成功后听 5s（远程配置）→ 切断 4G 电源 → 灯效结束回 SLEEP。

软关机：BLE 休眠、清屏关 LCD、红灯 5s；主循环不用 DeepSleep（20ms Sleep 轮询霍尔），避免无法再开机。

状态灯效（DS2）
等 BLE绿灯闪（约 400ms 周期）
BLE 已连绿灯常亮
上报中（含霍尔感应起）绿灯闪直至发完
发送失败红灯闪 3 次
关机红灯亮 5s 后灭

LCD：休眠保持显示；软关机灭屏；上报前后刷新温湿度/电量，温湿度约 3s 交替。设备号优先取 Secure 区 0x1B000 的 DeviceId，无效时回退编译默认值，出现在上报 JSON 的 no 字段。

13.3 上报 JSON

数据包（evt=0/1/2/3）字段：no, seq, ok, t, rh, evt, csq, bat, bat_mv, ts（seq 仅数据包递增）。

0周期心跳

2霍尔 / AT+REPORT

13.5 远程配置（4G）

设备 TCP 上报成功后保持连接监听 5s，平台可下发一包 JSON（建议 ≤512B）完成参数配置与对时。含配置字段 → 写入 RAM 并落盘 UserCfg；含 "tt":<unix秒> → 校准设备时间。

该部分内容已独立为 4G 远程配置 文档，包含完整 JSON 字段表、配置示例与生效规则，请参见该文档。

13.6 实现注意

  1. BLE 与 USB 调试共 UART：BLE 保持连接时，USB 串口可能被 CH9141 抢答。
  2. 每次上报冷启动 4G：驻网可达数十秒～2 分钟，周期勿过短。
  3. 霍尔在屏 FPC/PF05：靠近后串口应见 H->L / SHORT；raw pin 应从 1→0。
  4. 型号版本以固件宏为准；Flash / 远程改 ver 仅临时有效，重启恢复 WW105C,200。
